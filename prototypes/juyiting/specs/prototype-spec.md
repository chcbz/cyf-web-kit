## 4. 共用卡片、控件和弹层详细规格

### C01 需求输入与草稿
- 文字、资料引用属于同一草稿；开始办事前不要求选Agent。无文字但有资料也不能因输入空白一律拒绝。
- 点击开始办事只产生一个创建意图；按钮忙态防重复。成功返回事项ID才进入待点将；网络未知保留原意图查询，不能新建另一事项。
- 返回、弹层取消、普通刷新保留允许保留的草稿；身份切换不能串用其他账号草稿。原型sessionStorage不是生产存储方案。

### C02 事项卡与状态筛选
- 标题、摘要、承办、状态、资料/结果或能力摘要；窄屏截断仅限非关键摘要，详情可读全文。
- 搜索、状态和能力组合过滤；空态区分没有事项与没有匹配结果。计数与同一数据源一致。
- 进入某卡恢复该事项上下文；不能把最后活跃事项的消息、成果或草稿带到另一卡。

### C03 待点将推荐与确认
- 同一详情内展示系统推荐理由、当前候选和“另选承办Agent”；另选为内联候选列表，不开另一条需求流程。
- 选择候选仅变更草稿选择；“确认承办，进入议事”成功才正式指派并进入议事。保存失败留在原事项；禁止重复创建/重复指派。
- Agent能力、在线、安装授权、技能就绪是不同事实，不能仅凭安装成功宣称可承办。无候选保持真实空态，本轮不增加接入引导。

### C04 事项进展卡
- 待点将：推荐、另选、确认；进行中：状态原因与继续议事；待验收：主“查看成果并验收”、次“继续议事”；已完成：历史议事/最终成果只读。
- 待验收详情不再重复显示“继续修改”按钮或验收摘要卡。点继续议事不变更状态。
- 验收操作未知显示原操作核对，锁定冲突写入；不能假设未执行而再验收。取消只在服务端真实允许时出现。

### C05 议事工具栏与话头记录
- 工具栏：事项/对象上下文、刷新、话头记录、新话头；图标有名称。不要把“新话头”解释为新事项。正式议事另保留默认折叠的本任务技能条，summary触控高度44px，空/有技能有明确示例，折叠不占消息正文。
- 话头记录在工具栏下展开/收起：标题、时间、当前选中、删除、再取旧话头；加载/空/失败独立展示。
- 切换恢复话头消息、草稿、附件和引用；删除需确认含标题，删除话头不删除事项和固定交付。录音期间按原锁限制切换。

### C06 消息和输入区
- 用户与Agent消息有角色区分；支持文本、资料引用、文字片段保存、明确问题及成果。**本轮只删除成果文件卡的保存按钮，不删除消息“保存文字片段”。**
- 正式议事输入不重复页头事项/固定承办人上下文；私人/公共保留各自传话对象。保留文字计数、更多、附件、语音及发送；当前原型计数1200，以接口约束另核验，不新增后台限额。
- 输入附件是紧凑条目/横向区域，显示文件名、预览、移除，不在输入区铺开多张大图；正文消息区保持可用高度。
- 发送成功才清空已提交草稿；失败/未知保留内容与附件，先查原请求；进行中可展示真实等待原因，但不新增主状态。

### C07 成果卡及紧凑操作（2026-10-26本会话收口）
- 同一轮一条Agent回复承载必要答复、执行状态与成果；不重复展示普通正文+同文typed答复卡，不把执行指令、完成通知及附件拆成四个独立响应区。实际好汉身份统一，不用通用“好汉”伪装成另一位响应者。
- 处理中在原回复内显示低强调“正在改图…”；已生成待登记显示“图片已生成，正在准备预览…”，没有已核验成果时不提供验收。成功后同一回复展示简短结论和实际图片/文件，撤下处理中占位，不重复“本轮完成／请查看会话中的答复或文件”卡。
- 正常运行不在页顶显示黄色“处理未交付的一轮”。未交付且服务端允许放弃时，在该轮回复的默认折叠“本轮操作”提供放弃；点击再确认费用不撤销、不保证服务商停止、已上传成果保留。取消继续等待，不自动放弃。未知结果可核对原请求，不自动重放生成；未知放弃操作只恢复原意图，不假装已完成。
- 内容：文件名、固定版本/来源、真实媒体；不能把示例文本或模型结束当作正式交付事实。多文件放在同一回复中，保留独立预览，禁止基于文案猜测绑定。
- 文件卡操作同排 `预览 / 验收此版`，后者仅在有资格的固定成果上出现，预选该版打开统一验收窗；只读不提供验收。顶部统一验收可默认不选，支持多选/历史版；打开、关闭均不提交。普通参考附件无验收入口，不设单独“议事成果”区或固定批次操作栏。
- 议事成果卡及议事内预览均不提供下载；不删除消息“保存文字片段”，不影响百宝箱/资料管理的下载。成果卡不提供“引用修改”；修改直接在原议事输入，目标不明确则澄清。
- 该合并是展示投影，不合并底层请求/步骤/消息记录，不改变身份、任务/版本、授权、费用、锁、摘要或验收契约。不同请求、不同来源的消息不按文本相似度折叠，真实澄清和失败不能隐藏。

### C08 资料选择弹层
- 页头返回，PC列表/详情分栏；正文弹性且各区独立滚动；底部选择计数、取消、完成固定。
- PC选择文件自动预览，不显示预览/关闭预览切换。手机选择后显示摘要与操作；**同一“预览 / 收起预览”按钮始终保留**，aria-expanded反映状态，收起回列表。
- 手机预览时顶部返回先回列表，不退出整个选择；再返回才取消。切换预览保留当前文件、暂存选择和焦点。
- 图片contain不裁切；文字可滚动、音频使用播放器。选择资料页移除“下载”按钮；预览不等于添加；添加进入暂存集合；完成才写入草稿，取消不提交。
- 已选清单按需展开，独立限高滚动，不随多选数量挤小主列表；重复添加禁用。PC/手机切换不丢选择。
- 2026-10-21 更新：底部“已选 x 份资料”后紧邻“上传资料”入口，PC/手机均支持多文件选择；上传成功自动加入当前暂存已选集合并定位首个新文件，不需要再逐个点“添加”；保留原有选择，点“完成”才带入需求/议事，不自动发送或交办。
- 取消系统选文件对话框不改变选择；读取期间禁用上传，失败保留原有选择并允许重试；退出选择器后异步结果不得写入其他选择器。完成上传后取消选材仅放弃本次引用，不删除已保存资料。
- 原型仅用本地文件读取模拟上传，不请求服务器、不代表生产云上传已实现；正式实现须以工作空间上传成功的资源ID/固定版本为准，不把临时本地ID当成服务端成功。独立预览和资料详情的下载不在此次移除范围。

### C09 独立资料预览
- 保留生产已有PDF分页、上一页/下一页、返回选材及选取当前资料后返回选择流程；完整媒体类型覆盖不以原型文字/图片/音频示例为上限。移动“预览/收起”是选择器内布局改版，不删除独立文档预览导航；有返回的页头不重复×，无返回独立弹窗保留关闭。
- 标题、内容、标准关闭图标；议事中打开的图片/文字/音频/文件预览无下载及空操作栏，音频 controlslist="nodownload"。百宝箱/资料管理等非议事独立预览仍可下载。原型三页PDF按文本分片演示，上下页更新内容及页码、边界禁用，不宣称任意PDF解析可用。关闭只退当前层，回验收弹层不清除冻结集合。
- 图片按容器contain；错误/格式不支持给真实说明，不显示空白假成功。关闭恢复触发控件焦点；Escape先处理顶层弹窗。

### C10 验收确认及操作恢复
- “查看并验收”先打开确认：本轮N项固定成果、预览、结束后只读说明、返回修改、确认验收；打开/关闭本身不提交决定。
- 确认时冻结事项/指派版本、交付批次/成果版本、幂等意图；成功才已完成。重按不产生第二写入。
- 返回修改只进入同议事准备输入；真正提交修改才记录旧交付要求修改并开始新轮次；普通提问不能默认为拒收。
- 未知/失败按原操作核对及服务端允许的恢复继续；保留必要进度提示，不因移除普通待验收条而删掉恢复入口。

### C11 语音输入
- 在同一输入框内切换文字→录音→转写预览，不在下面追加录音区。取消恢复原草稿，停止后转写可编辑；追加/替换只改草稿，仍手动发送。
- 空转写不覆盖草稿；真实录音需权限、错误和取消处理；原型不调用麦克风，不把示意波形/文本当识别成功。

### C12 点将册详情与技能
- 名册、当前选中、技能/本领内容、刷新与操作区分层。PC独立滚动，手机详情替换列表；操作条不随长技能列表消失。
- 技能的已核验安装/运行就绪、未核验、空目录和读取失败分别展示；刷新失败不留旧就绪，切换Agent时迟到响应不得覆盖新对象。
- 密议与承办确认按实际上下文呈现，确认传明确Agent ID；不复用隐式上次选中值。

### C13 取消、删除、归档
- 删除文件/话头、取消事项、个人收入案卷不是同一种动作，分别命名和确认。
- 取消仅按服务端支持范围；请求未知查原操作；取消不是Provider已停止或已退款。归档不触发验收。
- 已完成/已取消保留可读历史；不能通过重开页面、改标签或引用按钮绕过终态。

### C14 辅助反馈与安全
- Toast可作即时辅助，不代替持久错误/未决操作说明；loading、empty、error不共享模糊“等待执行”。
- 权限与来源在服务端校验；示例台账、令牌、Runtime安装状态不作为业务事实。正文/文件名不直接插入不可信HTML。

## 5. 四阶段与触发规则

| 当前 → 下一状态 | 谁触发 | 成功条件 | 未满足时 |
|---|---|---|---|
| 草稿 → 待点将 | 用户开始办事、系统保存 | 同一创建意图保存事项和资料引用成功 | 失败留草稿；未知查原意图 |
| 待点将 → 进行中 | 用户确认承办 | 身份/权限/候选版本通过、指派成功 | 保留已保存事项和候选，不重建 |
| 进行中 → 进行中 | Agent提问、用户回复/授权、系统执行 | 对同一事项/问题/请求版本持久关联 | 等待、澄清、失败原因在议事呈现，不添加筛选状态 |
| 进行中 → 待验收 | Agent表达交付意图、系统正式提交 | 有效固定交付，授权/版本校验成功，无冲突未决修改 | 有普通结果不够，不能前端自行标待验收 |
| 待验收 → 进行中 | 用户发送明确修改要求 | 旧批次返工决定成功，新轮次关联原版本 | 只打开输入框/普通聊天不改变阶段；未知核对原操作 |
| 待验收 → 已完成 | 用户明确确认验收 | 服务端验收成功或查询证实原验收成功 | 保留待验收及核对提示，不重复提交 |
| 可取消阶段 → 已取消 | 用户取消、系统核验 | 接口允许且确认取消成功 | 不伪造停止/退款；作为历史标记，不加入四主步骤 |

四主状态是用户投影，不删除后端执行/操作/交付状态。根failed、archived及未知枚举不能伪装为正在计算或可重试；显示真实结束原因和合法动作，其映射合同需在实现前补齐（方案B03）。

## 6. 共用与分开

- 共用：页头、主题token、按钮、输入/录音/资料、消息媒体、话头记录、预览、错误反馈；首页/提出需求共用创建意图和同一事项ID。
- 分开：正式事项与私人/公共议事的身份、可见范围、存储、执行与验收权；正式交付决定与普通成果展示；资料版本与个人整理标记；真实费用与演示反馈。
- 不允许用“共用组件”直接混合权限或复用其他事项旧回执。旧私人事项保留访问，不自动转成公开TASK。

## 7. 当前原型仍需收口的明确差异

1. `results`页现已与议事共用`reviewAcceptance`：返回议事只导航，“查看并验收”冻结同一集合，确认弹窗才出现“确认验收”。原型修正不等于产品共享批次合同已实现。
2. `renderUnifiedResults`与既有正式成果页面不是完全等价；生产一键验收在用户明确点击后包含submit+accept（事项466已实测），不是未经同意自动验收；原型自动“提交”只是fixture。必须补真实合同，不能按有文件就接通验收。
3. 根失败/归档等终态的四阶段投影尚未有完整生产合同；未知枚举不得静默落到进行中。原型详情已有原因提示不等于完整后台覆盖。
4. 公共议事真实入口、账户设置、边界断点/真机键盘等尚需复核；技能折叠工具条已补入原型，支持空/有技能示例，不表示真实授权；不因原型19页都有HTML就认定生产逐页一致。
5. 演示索引、示例数据、场景参数、revision和离线标志不进入产品；不照搬原型JS状态机、固定延时、sessionStorage或整份snapshot CSS。

## 自然语言修改交互（2026-10-18）
- 用户决定，Agent理解，后端控制状态，前端呈现；原型仅模拟，不连接真实Agent/后端。
- 待验收时直接输入“把时间改成明天，重新生成”可演示进行中→新成果待验收，旧成果保留。无需点引用修改。
- 输入“改成明天会不会更好？”先在原议事澄清，不变更待验收；可回复明确修改要求。输入“这个结果怎么理解？”只讨论；“不错”“可以”不自动验收。
- 多成果未定位或引用历史成果时先问清，不默认替换全部；不新增引用按钮；用成果名称或内容定位。
- PC/移动共用同一输入和内联回复，不加返工弹窗/独立主状态；验收仍由当前批次成果卡按钮打开既有确认框。
- 离线原型只支持以上固定示例及少量变体，其他表达保守澄清；不是生产意图分类器，不以关键词脚本代替产品实现。生产未知/重试/并发能力按本次详设实施及正式验证。
